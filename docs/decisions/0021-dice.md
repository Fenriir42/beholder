# 0021: Dice rolls

## Context

SPEC §5.5 asks for dice rolled from the sheet with the computed modifiers, made on the server as the single authoritative path (the future Discord bot will reuse it), a live shared roll log, secret DM rolls, physical dice entry, and structured roll events. The user chose to let players also roll "to the DM", to keep the last 50 rolls, and to show one's own rolls as a card on the sheet while everyone's go to the log.

## Decision

- **`core::dice`:** `Expr` (dice terms with keep-highest or keep-lowest, plus a modifier) parses `NdM`, `+/-`, `khN`/`klN` and the `adv`/`dis` shortcuts, within 100 dice, 1,000 sides and 10 terms. It displays as normalized notation. `roll(expr, die)` takes the random source as a function and returns an `Outcome` with every die and which ones were kept. `Expr::from(Roll)` turns the sheet's computed values (ADR-0020) into expressions, and `with_advantage` and `critical` adapt them.
- **Commands and events:** `CommandKind::Dice { campaign_id, op }` carries `DiceOp::Roll` or `DiceOp::Physical` (with one result per die, checked against each die's size), a context, the character's name and a `Visibility` of `Public` or `ToDm`. The server rolls with the operating system's random source, using rejection sampling so every face is equally likely, and emits `CampaignEvent::Rolled { roll: RollRecord }`. The roll's id is the command id, so the client can tell its own result apart.
- **Visibility on the server:** `permissions::can_see_roll` lets everyone see a public roll, and the roller and DMs see a roll to the DM. A DM's roll to the DM is the secret DM roll. Events and snapshots are filtered with it, and the rule is in the permission matrix.
- **Log size:** `Campaign.rolls` keeps the last 50 rolls (`LOG_SIZE`). The server stores them in a `rolls` table pruned on insert. The snapshot gained a field, so `PROTOCOL_VERSION` is now 7 and the client cache schema is now 6.
- **Interface:** a `Roller` holds the advantage choice, the "to the DM" toggle, the character's name and the last roll id. The sheet's saves, skills, ability checks, initiative, attacks, damage and healing call it. d20 tests include the 2024 exhaustion penalty, and an attack keeps its doubled damage expression for a natural 20. The Dice log screen shows the log, a free-form roll box and physical entry.

## Alternatives

- **Rolling on the client:** instant, but not authoritative, and the Discord bot couldn't share the path.
- **A roll history outside the campaign snapshot:** unlimited history, but a second sync path. 50 rolls cover a session, and older ones stay in the event log until compaction.
- **A crate for dice notation:** existing parsers bring more syntax than needed and their own random number handling, while the subset needed here fits in one tested module.

## Consequences

- Rolls need a connection. While offline, a roll waits in the outbox and the sheet shows "Rolling…" until the server answers.
- Advantage applies to the first single d20 of an expression, which covers sheet rolls and typed `d20` rolls.
